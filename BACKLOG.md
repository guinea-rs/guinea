# Бэклог

## Адаптивная композиция: области, брейкпоинты и вместимость

Обсуждено 1 ноября 2026. Концепт одобрен; реализация и окончательный API
отложены. Цель — предоставить инфраструктуру, чтобы каждое приложение
не реализовывало измерения, подписки и обработку изменения размеров заново.

- Базовая сущность — измеряемая область: клиентская область окна либо
  конкретный контейнер. Контейнер получает пространство от родительской
  раскладки; разные экземпляры компонента имеют независимые области.
- Размеры — в логических единицах с учётом масштабирования бэкенда.
  Приложение объявляет собственные категории и пороги, например
  0 / 640 / 960 / 1600. Инфраструктура уведомляет потребителей брейкпоинтов
  при смене категории, а не на каждый пиксель изменения размера.
- Эскиз DX: `cx.window_area()`, `cx.container_area()`,
  `cx.breakpoint::<Width>(area)` и привязка элемента
  `Grid::new().observe_area(area)`. Это предложения, не существующий API.
  Область стабильна между перестроениями; подписки освобождаются вместе
  с компонентом. Для периода до первого измерения нужна явная политика.
- Смена категории меняет представление; она сама по себе не должна
  переустанавливать фичи, перемонтировать неизменившиеся дочерние компоненты
  или сбрасывать их состояние. Приложение выбирает композицию.
- Отдельный сценарий — подбор представления по вместимости содержимого.
  Пример: панель действий Services в uniproc. При нехватке места сначала
  скрываются подписи части кнопок, затем менее важные команды уходят в `…`.
  Пороги зависят от состава действий, локализации и метрик шрифта;
  фиксированной ширины окна или контейнера здесь недостаточно.
- Для подбора нужны измерения требуемого места альтернативных вариантов:
  свободное место после скрытия подписей ещё не означает, что полный вариант
  снова поместится. Учитывать отступы, разделители и кнопку overflow.
- Защита от дребезга — гистерезис: сжимать при нехватке места,
  возвращать расширенный вариант только при наличии дополнительного запаса
  (условно 16 логических единиц; значение настраивается). Задержка по времени
  не заменяет устойчивый алгоритм измерений. Избегать циклов, когда содержимое
  определяет размер измеряемой области и одновременно меняется от него.
- Распределение ответственности: общие области, категории и жизненный цикл
  подписок — инфраструктура интеграции; нативные измерения и размещение —
  бэкенд/контрол. Сначала использовать готовые механизмы toolkit, где подходят.
  В WinUI есть [CommandBar с динамическим overflow](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.controls.commandbar.isdynamicoverflowenabled)
  и `DynamicOverflowOrder`; доступность в текущем windows-reactor и пригодность
  для панели отдельно проверить. Не писать собственный аналог заранее.
- При реализации проверить харнесом: границы порогов, независимые контейнеры,
  начальное измерение, очистку подписок, сохранение состояния при resize,
  изменение текста/шрифта/набора команд и отсутствие дребезга у границы.

## Локальное оформление нативного поля поиска

Отложено 30 октября 2026. Issue не опубликован; vendor не менять.

- Скретчпад: [описание и запуск](../uniproc/diagnostics/reactor-ui/SEARCH.md),
  [код](../uniproc/diagnostics/reactor-ui/src/bin/search_box.rs).
- Нативный TextBox высотой 32 DIP, радиусом 16 DIP и padding 44,4,12,4;
  декоративная лупа пропускает указатель к полю. Сохраняются нативные
  редактирование, IME, фокус и состояния WinUI.
- Для интеграции нужны публичные TextBox.Padding/CornerRadius,
  IsHitTestVisible у декоративных элементов и ресурсы на уровне поля
  или его поддерева. Полный дизайн также требует ThemeDictionaries и
  LinearGradientBrush с затуханием верхней подсветки за 2 DIP.
- В текущем windows-reactor ResourceOverrides доступен для Button/Expander
  и поддерживает только цвет, толщину и радиус. Возможная альтернатива
  расширению деклараций — поддержанный локальный native Style/Resources bridge.
- Скретчпад устанавливает неявные стили через Application.Resources.
  Это демонстрация: в продукте ресурсы должны быть локальными, без глобальной
  перестилизации TextBox/TextBlock и без замены нативного шаблона поля.
- Дальше: запросить недостающий API upstream и затем подключить оформление
  в uniproc. Готового публичного пути для точного дизайна пока нет.

## Изображения в WinUI Reactor

Отложено 22 октября 2026. Не менять вендор для обхода этих проблем.

### Повторная загрузка изображений при возврате на страницу

- В репро страница A содержит одну иконку, B — 27. PNG-байты постоянные.
- При возврате на B её заголовок иногда появляется на 1–2 записанных кадра
  раньше остальных 26 иконок; запись велась с частотой 120 кадров/с.
- Воспроизводится через guinea с raw Image, через guicons и в отдельном
  репро на Reactor без guinea.
- В используемом windows-reactor-pre 0.105.0 кэш держит слабые ссылки на
  нативные источники. Освобождённые источники удерживаются только до конца
  текущего пакета изменений; возврат на страницу запускает загрузку заново.
- Контроль с постоянными невидимыми Image удерживает источники живыми:
  за пять записанных возвратов разрыва не было. Это диагностический приём,
  не предлагаемое исправление.
- Тест всех промежуточных пакетов guinea, включая сообщения обновления
  уходящей страницы, проходит на 32 seed'ах: общая иконка не уничтожается,
  её Source не сбрасывается. Отдельного пустого обновления в этом сценарии
  не обнаружено.
- Дальше: обсудить время жизни декодированного кэша и политику его очистки
  в апстриме. Стабильность исходных байтов не решает время жизни этого кэша.

### Качество SVG при масштабировании

- В чистом Reactor сравнивались одинаковые геометрии пяти SystemTools-иконок
  в Image размером 32×32.
- Исходные SVG с 1em, явными 24×24 и только viewBox дают одинаковый
  замыленный результат. При явных 32×32 результат чище; при 128×128
  заметны ступеньки. Контроль — PNG, полученный через resvg.
- Полутоновые пиксели на границах есть: полного отключения сглаживания
  не обнаружено. Точная причина зависимости от внутренних размеров пока
  не установлена.
- Дальше: закончить сравнение загрузки SVG из памяти и по файловому URI;
  проверить фактическое разрешение растеризации и RasterizePixelWidth/Height,
  момент загрузки относительно включения Image в живое дерево и DPI.

Локальные репро и записи находятся в игнорируемом target:
guinea-image-repro, reactor-routing-repro, png-guinea-raw-primary.mkv,
png-reactor-desktop.mkv, png-guicons-desktop.mkv, png-reactor-kept.mkv,
svg-quality-capture.png. Эти артефакты не входят в репозиторий.
